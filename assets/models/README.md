# サンプルモデル

このフォルダのモデルは、**すべて本リポジトリで作成したもの**です。
外部から取り込んだデータは含まれていません。

| ファイル | 内容 | ねらい |
|---------|------|--------|
| `torus.obj` | ドーナツ形。頂点 561 / 四角形 512 | 滑らかな法線と UV の繰り返しを確認する |
| `pyramid.obj` | 四角錐。頂点 5 / 面 5 | 手で読める大きさ。法線の自動生成と右手系変換を確認する |
| `scene.glb` | 球 2 つと箱 1 つ。頂点 894 / 三角形 1580 | GLB 形式とノードの変換を確認する |
| `sphere.gltf` ＋ `sphere.bin` | 球。頂点 561 / 三角形 1024 | JSON テキスト形式と外部バイナリの参照を確認する |

## torus.obj

大半径 1.0、小半径 0.38、分割 32 × 16 の円環面を計算で並べたものです。
`v` / `vt` / `vn` / `f` をすべて含み、面は四角形で書かれています
（読み込み側で三角形に分割します）。

閉じた曲面なので、**面の向きや法線が壊れているとすぐ分かります**。
裏返れば穴の内側が見え、法線が狂えば陰影がまだらになります。

## pyramid.obj

テキストエディタで開いてそのまま読める大きさにしてあります。

- **`vn` をわざと書いていません。** 読み込み側が面の向きから法線を作る経路を通ります。
- **頂点を +Z 側へ傾けてあります。** OBJ の +Z は手前なので、
  右手座標系から左手座標系への変換が正しければ、頂点は手前側へ傾いて見えます。
  変換を忘れると奥側へ傾き、前後が鏡写しになったことが分かります。

詳しくは [解説 15 章](../../docs/tutorial/15_モデルを読み込む_OBJ.md) を参照してください。

## scene.glb

3 つのノードに、球 2 つと箱 1 つを置いたシーンです。

- **箱**は `scale [1.4, 1.0, 1.4]` で軸ごとに違う倍率を掛け、Y 軸まわりに 45 度回転
- **球**は `translation` で上に積み、もう 1 つを小さくして横へずらしてあります

ノードの平行移動・回転・**軸ごとに違う拡大縮小**が正しく効いているかを、
読み込み後のバウンディングボックス（`1.980 x 2.050 x 1.980`）で確かめられます。

Z 方向に非対称なので、右手系から左手系への変換を忘れた場合も見分けが付きます。

材質を 3 つ持たせてあります。

| 材質 | 内容 | ねらい |
|------|------|--------|
| BaseTeal | 色のみ | テクスチャを持たない材質の経路 |
| HeadBanded | 色 ＋ **埋め込み PNG** | 画像がファイル内にある経路 |
| NoseAmber | 色のみ（強い色） | 材質ごとに切り替わることの確認 |

埋め込み PNG は横縞なので、球の V が反転していればすぐ分かります。

## sphere.gltf + sphere.bin

JSON テキストと外部バイナリに分かれた形式です。
`buffers[0].uri` が `sphere.bin` を指しているので、
**外部ファイルを開く経路**を通ります。

> **注意**: これらのサンプルは本リポジトリで書き出したものです。
> 読み込み側と書き出し側が同じ解釈をしているため、
> **仕様の読み違いがあっても一致してしまう**という弱点があります。
> 本来は Blender などが書き出したファイルでも確認すべきところです。
