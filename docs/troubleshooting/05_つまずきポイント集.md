# 05. つまずきポイント集（症状別・原因逆引き）

DirectX 12 は **間違えてもコンパイルは通り、実行時にも例外が出ず、ただ「何も映らない」**
ということが頻繁に起きます。症状から原因を引けるようにまとめました。

---

## 0. まず最初にやること：デバッグレイヤーを確認する

起動ログに次の行があるか確認してください。

```
[INFO ] デバッグレイヤーを有効化しました（Debug ビルド）。
```

出ていない場合は、Windows の設定から **Graphics Tools** をインストールしてください
（[01 章](../setup/01_ビルドと実行方法.md#推奨-graphics-tools-のインストール)）。

デバッグレイヤーが有効なら、API の誤用は
Visual Studio の「出力」ウィンドウに具体的なメッセージとして表示されます。
**この一手間で解決時間が 10 分の 1 になります。**

---

## 症状 1: ウィンドウは出るが、真っ黒（クリア色すら出ない）

| 原因 | 確認する箇所 |
|------|------------|
| `Present()` を呼んでいない | `Renderer::Render` の末尾 |
| コマンドリストを `Close()` していない | `Close()` 忘れは `ExecuteCommandLists` でエラーになる |
| `ExecuteCommandLists` を呼んでいない | 記録しただけでは GPU は動かない |
| RTV のハンドルが間違っている | `CurrentRenderTargetView()` の `ptr` 計算 |
| バリアを張っていない | `PRESENT → RENDER_TARGET` |

---

## 症状 2: 背景（クリア色）は出るが、三角形が出ない

**最も多い症状です。** 上から順に確認してください。

### 2-1. シザー矩形が 0 のまま ★最頻出

```cpp
m_scissorRect = {};   // ← これだけだと right=0, bottom=0 で全ピクセルが捨てられる
```

`RSSetScissorRects` は **設定必須**です。ビューポートだけでは足りません。

> 該当コード: [`Renderer::UpdateViewportAndScissor`](../../src/Graphics/Renderer.cpp)

### 2-2. 頂点の並び順（ワインディング）が逆 ★次点

DirectX の既定では **時計回りに見える面が表**です。
反時計回りだと裏面と判定され、背面カリングで消えます。

**切り分け方法:**

```cpp
// TrianglePipeline.cpp のラスタライザ設定を一時的に変更する
rasterizerDesc.CullMode = D3D12_CULL_MODE_NONE;   // BACK → NONE
```

これで表示されたなら、原因は頂点の並び順です。

### 2-3. 座標が NDC の範囲外

頂点座標は **-1.0 〜 +1.0** の範囲でなければ画面に入りません。
`(0, 100, 0)` のようなピクセル単位の値を入れると、遥か画面外に飛びます。

（座標変換行列を導入するまでは NDC で直接指定します）

### 2-4. `SampleMask` が 0

```cpp
psoDesc.SampleMask = UINT_MAX;   // ← 0 にすると何も描画されない
```

`D3D12_GRAPHICS_PIPELINE_STATE_DESC` をゼロ初期化したまま設定を忘れると
`SampleMask = 0` になり、全ピクセルが破棄されます。

### 2-5. `SetPipelineState` / `SetGraphicsRootSignature` を呼んでいない

コマンドリストは `Reset` するたびに設定が消えます。**毎フレーム設定が必要**です。

### 2-6. `IASetPrimitiveTopology` を呼んでいない

PSO の `PrimitiveTopologyType`（大分類）だけでは足りず、
コマンドリスト側で `D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST`（具体的な結び方）の指定が必要です。

### 2-7. 頂点シェーダーが `w` を設定していない

```hlsl
output.position = float4(input.position, 1.0f);   // ← w = 1.0 が必要
```

`w = 0` だと透視除算でゼロ除算になり、結果が壊れます。

## 症状 3: 三角形は出るが、色や形がおかしい

### 3-1. 入力レイアウトのオフセットがずれている

**3 か所が一致している必要があります。**

```cpp
// (1) C++ の構造体
struct Vertex {
    float position[3];   // オフセット  0、12 バイト
    float color[4];      // オフセット 12、16 バイト
};

// (2) 入力レイアウト
{ "POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT,    0,  0, ... },
{ "COLOR",    0, DXGI_FORMAT_R32G32B32A32_FLOAT, 0, 12, ... },  // ← 12 が正しいか
```

```hlsl
// (3) HLSL
struct VSInput {
    float3 position : POSITION;   // ← float3 と R32G32B32 が対応
    float4 color    : COLOR;      // ← float4 と R32G32B32A32 が対応
};
```

**症状の見え方:** 形が崩れる／色が真っ黒や真っ白になる／頂点が飛ぶ。

### 3-2. `StrideInBytes` が構造体サイズと違う

```cpp
m_vertexBufferView.StrideInBytes = sizeof(Vertex);   // ハードコードしない
```

### 3-3. セマンティクス名の綴り違い

`"COLOR"` と `"COLOUR"`、`"POSITION"` と `"POSITIONS"` など。
**コンパイルは通ります。** その要素だけ値が 0 になります。

## 症状 3b: 座標変換を入れたら三角形が消えた・潰れた

### 3b-1. 行列を転置していない ★最頻出

C++ の DirectXMath は**行優先**、HLSL の定数バッファは既定で**列優先**です。
そのまま渡すと転置された行列として解釈されます。

```cpp
// 正しい
XMStoreFloat4x4(&constants.worldViewProjection, XMMatrixTranspose(wvp));

// 間違い（転置忘れ）
XMStoreFloat4x4(&constants.worldViewProjection, wvp);
```

**症状の見え方:** 三角形が画面外へ飛ぶ／潰れて線になる／変な方向に歪む。

### 3b-2. `mul()` の引数の順序が逆

```hlsl
mul(float4(input.position, 1.0f), g_wvp)   // 行ベクトル規約（DirectXMath と同じ）
mul(g_wvp, float4(input.position, 1.0f))   // 列ベクトル規約
```

転置の有無と組み合わせで 4 通りあり、正しいのは 2 通りだけです。
**「CPU で転置する + `mul(位置, 行列)`」**の組み合わせに統一するのが安全です。

### 3b-3. `w` を 1.0 にしていない

```hlsl
float4(input.position, 1.0f)   // ← 0.0f にすると透視除算でゼロ除算になる
```

### 3b-4. 回転させたら形が歪む

アスペクト比の補正が入っていません。
NDC は正方形ですが、ウィンドウは横長です。

```cpp
const XMMATRIX aspectCorrection = XMMatrixScaling(1.0f / aspectRatio, 1.0f, 1.0f);
```

### 3b-5. 定数バッファのサイズが 256 バイト境界に揃っていない

デバッグレイヤーが次のようなエラーを出します。

```
D3D12 ERROR: CreateConstantBufferView: SizeInBytes must be a multiple of 256
```

```cpp
const uint32_t alignedSize = (sizeInBytes + 255) & ~255u;
```

### 3b-6. 定数バッファを 1 個しか用意していない

フレームバッファリングと併用すると、
**CPU が書き込んでいる領域を GPU がまだ読んでいる**状態が発生します。

**症状の見え方:** ちらつく／回転がガタつく／たまに 1 フレームだけ飛ぶ。
再現性が低く、Debug ビルドでは気付きにくいのが厄介です。

コマンドアロケータと同様に、バックバッファの枚数ぶん用意してください。

### 3b-7. HLSL の `register(b0)` と C++ の番号が食い違う

```cpp
rootParameters[0].Descriptor.ShaderRegister = 0;   // ←→ HLSL: register(b0)
```

なお、`SetGraphicsRootConstantBufferView` の第 1 引数は
**ルートパラメータの番号**であって `b0` の `0` ではありません。
たまたま両方 0 のことが多いため、混同したまま気付かないことがあります。

## 症状 3c: 深度バッファを入れたら描画がおかしくなった

### 3c-1. 前後関係が逆に見える

`DepthEnable` が `FALSE` のままです。この場合
**あとから描いたものが必ず手前**になります。

```cpp
depthStencilDesc.DepthEnable    = TRUE;
depthStencilDesc.DepthWriteMask = D3D12_DEPTH_WRITE_MASK_ALL;
depthStencilDesc.DepthFunc      = D3D12_COMPARISON_FUNC_LESS;
```

`OMSetRenderTargets` の第 4 引数に DSV を渡し忘れている場合も同じ症状になります。

### 3c-2. 1 フレーム目は正常、2 フレーム目から真っ暗／ちらつく

`ClearDepthStencilView` を呼んでいません。
前フレームの深度が残るため、2 フレーム目以降のピクセルが
「すでに手前に何か描かれている」と判定されて全部捨てられます。

### 3c-3. PSO の生成が失敗する

`DSVFormat` が深度バッファの実際のフォーマットと食い違っています。

```cpp
psoDesc.DSVFormat = DepthBuffer::kFormat;   // DXGI_FORMAT_D32_FLOAT
```

### 3c-4. DSV の作成でエラーになる

リソース作成時に `D3D12_RESOURCE_FLAG_ALLOW_DEPTH_STENCIL` を立て忘れています。
このフラグが無いと「深度バッファとしては使えないリソース」になります。

### 3c-5. クリア値についての警告が出る

```
D3D12 WARNING: ClearDepthStencilView: The application did not pass a clear value
that matches the optimized clear value
```

`CreateCommittedResource` に渡した `D3D12_CLEAR_VALUE` と、
`ClearDepthStencilView` に渡す値が違います。両方 `kClearDepth` を使ってください。

### 3c-6. リサイズすると落ちる／エラーになる

深度バッファをレンダーターゲットと同じ解像度に作り直していません。
`Renderer::Resize` で **スワップチェーンと深度バッファの両方**を
リサイズする必要があります。

### 3c-7. 三角形が消える（z が範囲外）

深度は **0.0〜1.0** の範囲でなければなりません。
`DepthClipEnable = TRUE` のため、範囲外の頂点は切り取られます。
座標変換を入れていない段階では、頂点の z を 0.0〜1.0 に収めてください。

## 症状 4: 実行中にクラッシュ・デバッガが止まる

### 4-1. `SetBreakOnSeverity` によるブレーク（正常な動作）

```cpp
infoQueue->SetBreakOnSeverity(D3D12_MESSAGE_SEVERITY_ERROR, TRUE);
```

これは**わざと止めています**。「出力」ウィンドウにエラーの内容が出ているので読んでください。
原因の場所で止まっているため、最も解決しやすい状態です。

### 4-2. コマンドアロケータを GPU 実行中に Reset

```
アロケータの Reset は、そのアロケータで記録した命令の実行完了後でなければならない
```

本プロジェクトは毎フレーム `Flush()` しているため発生しませんが、
フレームバッファリングに改造したときに最も嵌まりやすい箇所です。

### 4-3. `StateBefore` が実際の状態と違う

```cpp
barrier.Transition.StateBefore = D3D12_RESOURCE_STATE_PRESENT;   // 実際と一致必須
```

DirectX 12 はリソースの状態を追跡してくれません。開発者が正しく把握する必要があります。

### 4-4. リサイズ時にバックバッファの参照が残っている

`ResizeBuffers` の前に **すべての参照を手放す**必要があります。

```cpp
for (auto& backBuffer : m_backBuffers) {
    backBuffer.Reset();   // ComPtr の参照カウントを減らす
}
```

1 つでも残っていると `DXGI_ERROR_INVALID_CALL` で失敗します。

### 4-5. 終了時にクラッシュ・リソースリーク警告

GPU の作業完了を待たずにリソースを解放しています。

```cpp
renderer.WaitForGpu();   // 終了前に必ず
```

## 症状 5: シェーダーが読み込めない・コンパイルエラー

### 5-1. `アセットファイルが見つかりません`

作業ディレクトリの問題です。ログに探索した場所が出力されます。

```
[ERROR] アセットが見つかりません: shaders/Triangle.hlsl
[ERROR]   カレントディレクトリ : ...
[ERROR]   実行ファイルの場所   : ...
```

| 起動方法 | 設定箇所 |
|---------|---------|
| Visual Studio | `.vcxproj` の `LocalDebuggerWorkingDirectory` |
| VSCode | `.vscode/launch.json` の `cwd` |
| 直接実行 | `ResolveAssetPath` が exe の親方向を探索するので通常は問題なし |

### 5-2. HLSL の文法エラー

コンソールと Visual Studio の「出力」ウィンドウに、
行番号付きのエラーメッセージが出力されます。

```
Triangle.hlsl(42,5-20): error X3004: undeclared identifier 'colr'
```

`TrianglePipeline::CompileShader` が `errorBlob` の中身を必ず出力するようにしてあります。
**HRESULT だけ見ても原因は分かりません。** errorBlob を読んでください。

### 5-3. エントリポイント名の不一致

```cpp
CompileShader(path, "VSMain", "vs_5_0");   // ← HLSL 側の関数名と一致必須
```

## 症状 6: ビルド関連

| エラー | 原因と対処 |
|-------|-----------|
| `LNK2019: 未解決の外部シンボル IID_ID3D12Device` | `dxguid.lib` をリンクしていない |
| `LNK2019: D3D12CreateDevice` | `d3d12.lib` をリンクしていない |
| `LNK2019: D3DCompileFromFile` | `d3dcompiler.lib` をリンクしていない |
| `LNK2019: CreateDXGIFactory2` | `dxgi.lib` をリンクしていない |
| 警告 C4819 / コメントが文字化け | コンパイルオプションに `/utf-8` が無い |
| `error C2039: 'format': is not a member of 'std'` | C++20 を指定していない（`LanguageStandard` を `stdcpp20` に） |
| `error MSB4025: XML コメントの内部に '--' を含めることはできません` | `.vcxproj` のコメント内にハイフン連続がある |

## 便利な切り分けテクニック

### 1. ワイヤーフレーム表示

```cpp
rasterizerDesc.FillMode = D3D12_FILL_MODE_WIREFRAME;
```

「三角形は描かれているが色が黒」なのか「そもそも描かれていない」のかを判別できます。

### 2. クリア色を派手にする

```cpp
constexpr float kClearColor[4] = { 1.0f, 0.0f, 1.0f, 1.0f };  // マゼンタ
```

クリアすら効いていないのかを一目で判定できます。

### 3. ピクセルシェーダーで固定色を返す

```hlsl
float4 PSMain(VSOutput input) : SV_TARGET
{
    return float4(1, 1, 0, 1);   // 黄色固定
}
```

黄色い三角形が出れば、**ジオメトリ（頂点処理）は正しく、色の受け渡しに問題がある**と分かります。

### 4. カリングを切る

```cpp
rasterizerDesc.CullMode = D3D12_CULL_MODE_NONE;
```

これで出るなら頂点の並び順の問題です。

### 5. Visual Studio のグラフィックスデバッガ

`Alt + F5` でグラフィックスデバッグを開始し、`Print Screen` でフレームをキャプチャ。
描画命令を 1 つずつ辿り、各段階での状態を確認できます。
「どの設定が想定と違うか」を直接見られるため、行き詰まったときに極めて有効です。
