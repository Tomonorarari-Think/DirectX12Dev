# 07. 動かす：定数バッファと行列

三角形を回転させます。ここで初めて「シェーダーに値を渡す」ことをします。
対応するコードは [`MeshPipeline::Update`](../../src/Graphics/MeshPipeline.cpp)、
[`ConstantBuffer`](../../src/Graphics/ConstantBuffer.h) です。

---

## 1. 定数バッファとは

シェーダーに **「頂点ごとではなく、その描画全体で共通の値」** を渡す入れ物です。

| | 運ぶもの | 例 |
|--|---------|-----|
| 頂点バッファ | 頂点ごとに違う値 | 座標、色、UV |
| **定数バッファ** | 描画中ずっと同じ値 | 変換行列、時間、ライトの色 |

Unity の `Material.SetMatrix()` や `Shader.SetGlobalFloat()` が
やっていたことに相当します。

---

## 2. 座標変換の考え方

頂点の位置を動かすには、**行列を掛けます**。

```mermaid

    B --> C["× ビュー行列<br/>カメラに合わせる"]
    C --> D["× プロジェクション行列<br/>遠近感を付ける"]
    D --> E["画面上の位置"]

    style B fill:#ddf4ff,stroke:#0a4f9e,color:#1f2328
    style C fill:#eaeef2,stroke:#8c959f,color:#1f2328
    style D fill:#eaeef2,stroke:#8c959f,color:#1f2328
```

本プロジェクトはまだ 2D なので、実際に使うのは
**ワールド行列（Z 軸回転）とアスペクト比補正**だけです。
灰色の 2 つは Step 10 で導入します。

### 行列は 1 個にまとめる

3 個の行列を毎頂点で 3 回掛けるのは無駄です。
CPU 側で 1 個に合成しておけば、シェーダーは 1 回掛けるだけで済みます。

```cpp
const XMMATRIX world            = XMMatrixRotationZ(rotationAngle);
const XMMATRIX aspectCorrection = XMMatrixScaling(1.0f / aspectRatio, 1.0f, 1.0f);
const XMMATRIX worldViewProjection = world * aspectCorrection;
```

頂点が何万個あっても合成の計算は 1 回なので、これが定石です。

### アスペクト比の補正が要る理由

NDC は縦横どちらも -1〜+1 の**正方形**ですが、
ウィンドウは 1280×720 の**横長**です。
この正方形が横に 1.78 倍引き伸ばされて表示されます。

補正しないと、回転させたときに三角形が歪みます。
X 方向をあらかじめ `1 / アスペクト比` だけ縮めておけば、
引き伸ばされた結果が正しい形になります。

### 時間で回す（フレーム数ではなく）

```cpp
const float rotationAngle = totalSeconds * (XM_2PI / kSecondsPerRotation);
```

**フレーム数で進めてはいけません。**
120 fps の環境では 60 fps の 2 倍速く回ってしまいます。
Unity で `Time.deltaTime` を掛けるのと同じ理由です。

## 3. ★ 行列の転置 — 必ず一度は嵌まる罠

| | メモリ上の並び |
|--|--------------|
| C++ の DirectXMath | **行優先** (row-major) |
| HLSL の定数バッファ（既定） | **列優先** (column-major) |

そのまま渡すと転置された行列として解釈され、**絵が壊れます**。

```cpp
// 正しい：CPU 側で転置してから書き込む
XMStoreFloat4x4(&constants.worldViewProjection, XMMatrixTranspose(worldViewProjection));
```

「行優先で並べた M の転置」＝「列優先で並べた M」となって辻褄が合います。

### `mul()` の引数の順序

HLSL の `mul` は引数の順序で意味が変わります。

```hlsl
mul(v, M)   // v を「行ベクトル」とみなす（v × M）
mul(M, v)   // v を「列ベクトル」とみなす（M × v）
```

DirectXMath は行ベクトル規約なので、**`mul(位置, 行列)`** の順で書きます。

```hlsl
output.position = mul(float4(input.position, 1.0f), g_worldViewProjection);
```

> 転置の有無と `mul` の順序の組み合わせは 4 通りあり、正しいのは 2 通りだけです。
> 本プロジェクトでは「**CPU で転置 ＋ `mul(位置, 行列)`**」に統一しています。
> 出典: [DirectXMath プログラミングガイド | Microsoft Learn](https://learn.microsoft.com/windows/win32/dxmath/pg-xnamath-internals)

## 4. 定数バッファの 2 つのルール

![定数バッファのフレーム別レイアウト](../assets/constant-buffer-layout.svg)

### ルール 1：サイズは 256 バイト単位

定数バッファの先頭アドレスは 256 バイト境界に揃っている必要があります
（`D3D12_CONSTANT_BUFFER_DATA_PLACEMENT_ALIGNMENT`）。

64 バイトの行列 1 個しか入れなくても、確保するのは 256 バイトです。

```cpp
static constexpr uint32_t Align(uint32_t size)
{
    return (size + 255) & ~255u;   // 切り上げの定番の書き方
}
```

### ルール 2：フレームごとに別の領域を使う

**[05 章](05_GPUへの命令と同期.md)のコマンドアロケータとまったく同じ理屈です。**

CPU が定数バッファへ書き込むとき、
GPU はまだ前のフレームの描画で同じ場所を読んでいるかもしれません。
1 個を使い回すと描画途中で値が変わり、絵が壊れます。

**症状が厄介です。** ちらつく・回転がガタつく・たまに 1 フレームだけ飛ぶ、
といった形で現れ、再現性が低く気付きにくいのが特徴です。

```cpp
// フレーム番号ぶんアドレスをずらして書く
std::memcpy(m_mappedData + frameIndex * m_alignedSize, data, sizeInBytes);
```

### 永続マップ

`Map` / `Unmap` は毎フレーム呼ぶ必要がありません。
生成時に一度 `Map` して、破棄までポインタを持ち続けるのが定石です。

```cpp
DX_CHECK(m_resource->Map(0, &readRange, &mapped));   // 生成時に 1 回だけ
m_mappedData = static_cast<uint8_t*>(mapped);
```

## 5. シェーダーへの渡し方（3 種類）

| 種類 | 渡すもの | ヒープ | 本プロジェクトでの用途 |
|------|---------|-------|---------------------|
| ルート定数 | 32bit 値を直接 | 不要 | 未使用 |
| **ルートディスクリプタ** | GPU アドレス | **不要** | 定数バッファ (b0) |
| ディスクリプタテーブル | ヒープ上の範囲 | 必要 | テクスチャ（[09 章](09_テクスチャを貼る.md)） |

行列 1 個を渡すだけなので、**ルートディスクリプタ**を使います。
ディスクリプタヒープを導入せずに済むぶん、学ぶことが少なくて済みます。

```cpp
// ルートシグネチャ側
rootParameters[0].ParameterType = D3D12_ROOT_PARAMETER_TYPE_CBV;
rootParameters[0].Descriptor.ShaderRegister = 0;   // ←→ HLSL: register(b0)
rootParameters[0].ShaderVisibility = D3D12_SHADER_VISIBILITY_VERTEX;

// 描画時
commandList->SetGraphicsRootConstantBufferView(0, m_constantBuffer.GpuAddress(frameIndex));
```

```hlsl
cbuffer SceneConstants : register(b0)
{
    float4x4 g_worldViewProjection;
};
```

> `ShaderVisibility` を `VERTEX` に絞っているのは、
> 範囲を狭くするほど GPU が最適化しやすいからです。

## 6. 書き込んでよいタイミング

```cpp
// (0) このフレームのフェンスを待つ
m_commandQueue.WaitForFenceValue(m_frameFenceValues[frameIndex]);
// ...
// (2b) ここで初めて安全に書き込める
m_trianglePipeline.Update(frameIndex, aspectRatio, totalSeconds);
```

**待った後だから書き込めます。**
GPU はもう `frameIndex` 番の領域を読み終えています。

「フレームごとに分ける」対象はコマンドアロケータだけではない、
という点が重要です。

---

## 7. この章のまとめ

- 定数バッファは「描画全体で共通の値」を渡す入れ物
- 行列は CPU 側で 1 個に合成してから渡す
- NDC は正方形なので、横長ウィンドウではアスペクト比の補正が要る
- アニメーションは**フレーム数ではなく時間**で進める
- **CPU 側で転置してから渡す**。`mul(位置, 行列)` の順で書く
- 定数バッファは 256 バイト境界。フレームごとに別領域を使う
- `Map` は生成時に 1 回だけ（永続マップ）
- 行列 1 個ならルートディスクリプタで足りる

次は、複数の物体の前後関係を正しくします。
