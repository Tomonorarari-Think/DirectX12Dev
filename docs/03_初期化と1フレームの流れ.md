# 03. 初期化と 1 フレームの流れ

このプロジェクトが起動してから三角形が表示されるまで、何がどの順番で起きているかを追います。

---

## 1. 全体像

```
main()
 │
 ├─ (1) Window::Create()          ウィンドウを作る
 │
 ├─ (2) Renderer::Initialize()    DirectX 12 の初期化（下で詳述）
 │
 ├─ (3) SetResizeCallback()       サイズ変更を Renderer へ橋渡し
 │
 ├─ (4) while (ProcessMessages()) メインループ
 │        └─ Renderer::Render()   1 フレーム描画
 │
 └─ (5) Renderer::WaitForGpu()    GPU の完了を待って終了
```

---

## 2. 初期化の順序（Renderer::Initialize）

**この順序には必然性があります。** 依存関係を矢印で示します。

```
① デバッグレイヤーの有効化
    │  ★ デバイス生成より前でなければ効かない
    ↓
② DXGI ファクトリの生成
    │  （アダプタ列挙・スワップチェーン生成に必要）
    ↓
③ アダプタ（GPU）の選択
    │  ファクトリが必要
    ↓
④ D3D12 デバイスの生成
    │  アダプタが必要。以降すべての生成の起点
    ↓
⑤ 情報キューの設定
    │  デバイスが必要
    ↓
⑥ コマンドキュー + フェンスの生成
    │  デバイスが必要
    ↓
⑦ スワップチェーンの生成
    │  ★ ファクトリ・コマンドキュー・HWND の 3 つが必要
    │    （DX11 と違いデバイスではなくキューを渡す点に注意）
    ↓
⑧ RTV ディスクリプタヒープ + RTV の生成
    │  スワップチェーンのバッファが必要
    ↓
⑨ コマンドアロケータ + コマンドリストの生成
    │  デバイスが必要
    ↓
⑩ ルートシグネチャの生成
    ↓
⑪ シェーダーのコンパイル → PSO の生成
    │  ★ ルートシグネチャと「描画先の形式」が必要
    ↓
⑫ 頂点バッファの生成
    ↓
⑬ ビューポート / シザー矩形の設定
```

### 順序を間違えるとどうなるか

| 誤り | 結果 |
|------|------|
| デバッグレイヤーをデバイスの後に有効化 | 検証が一切効かない（エラーが出ないので気付きにくい） |
| スワップチェーン生成にデバイスを渡す | コンパイルは通らない（引数の型が違う） |
| PSO の RTVFormat とバックバッファの形式が不一致 | PSO 生成が失敗する |
| コマンドリストを Close せずに Reset | 最初のフレームでエラー |

## 4. 1 フレームの流れ（Renderer::Render）

```
┌─ CPU 側の作業（命令の記録） ─────────────────────────┐
│                                                        │
│  (1)  allocator->Reset()          ノートを消す         │
│  (2)  commandList->Reset()        記録開始             │
│  (3)  バリア PRESENT → RENDER_TARGET                   │
│  (4)  RSSetViewports / RSSetScissorRects               │
│  (5)  OMSetRenderTargets          描画先を指定         │
│  (6)  ClearRenderTargetView       背景を塗る           │
│  (7)  SetPipelineState / IASetVertexBuffers            │
│       DrawInstanced(3, 1, 0, 0)   三角形を描く         │
│  (8)  バリア RENDER_TARGET → PRESENT                   │
│  (9)  commandList->Close()        記録終了             │
│                                                        │
└────────────────────────────────────────────────────────┘
                          ↓
┌─ GPU へ引き渡し ───────────────────────────────────────┐
│                                                        │
│  (10) ExecuteCommandLists()   ← ここで初めて GPU が動く │
│  (11) swapChain->Present()    画面に表示               │
│  (12) commandQueue.Flush()    GPU の完了を待つ         │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### ポイント 1: (1)〜(9) の間、GPU は何もしていない

`DrawInstanced` を呼んだ時点では、GPU は 1 ミリも動きません。
これが DirectX 11 との最大の感覚の違いです。

### ポイント 2: 毎フレーム設定し直す必要があるもの

コマンドリストは `Reset` するたびに **設定が全て初期状態に戻ります**。
「初期化時に一度設定すれば OK」ではありません。

- ビューポート / シザー矩形
- レンダーターゲット
- パイプラインステート
- ルートシグネチャ
- 頂点バッファ
- プリミティブトポロジ

### ポイント 3: バリアは必ず往復させる

```
描く前 : PRESENT       → RENDER_TARGET
描いた後: RENDER_TARGET → PRESENT
```

戻し忘れると、次の `Present` でデバッグレイヤーがエラーを出します。

## 5. なぜ 2 枚のバックバッファを交互に使うのか

```
フレーム 0:  バックバッファ[0] に描く → Present → 表示は [0]、次は [1]
フレーム 1:  バックバッファ[1] に描く → Present → 表示は [1]、次は [0]
フレーム 2:  バックバッファ[0] に描く → ...
```

`SwapChain::CurrentBackBufferIndex()` は毎フレーム変わります。
自分で `(index + 1) % 2` と計算せず、必ず
`swapChain->GetCurrentBackBufferIndex()` に問い合わせてください
（DXGI 側の都合で番号の進み方が変わる場合があります）。

## 6. 現在の同期方式とその問題

### 現在の実装（分かりやすさ優先）

```
CPU: [記録]              [記録]              [記録]
GPU:        [実行][待機]        [実行][待機]        [実行]
     └──────────────┘  └──────────────┘
       CPU と GPU が交互にしか動いていない
```

毎フレーム末尾で `Flush()`（GPU の完了待ち）をしているため、
**CPU と GPU が並列に動けていません**。DirectX 12 の利点を捨てた実装です。

なぜこうしているかというと、

- コマンドアロケータの `Reset` は「GPU の実行完了後」でなければならない
- 最も単純にこの条件を満たす方法が「毎フレーム待つ」だから

です。まずこの形で全体像を掴むのが目的です。

### 改善方法：フレームバッファリング

```
CPU: [記録0][記録1][記録2][記録3]...
GPU:        [実行0][実行1][実行2]...
     └─ CPU が 1 フレーム先行できる
```

必要な変更は 3 点です。

1. **コマンドアロケータをバックバッファの枚数ぶん用意する**
   ```cpp
   std::array<ComPtr<ID3D12CommandAllocator>, kBackBufferCount> m_commandAllocators;
   ```
   フレーム N ではアロケータ `[N % 2]` を使う。
   GPU がまだ `[0]` を使っていても、CPU は `[1]` に記録できる。

2. **フレームごとのフェンス値を記録する**
   ```cpp
   std::array<uint64_t, kBackBufferCount> m_frameFenceValues;
   ```

3. **Present 後は「全完了」ではなく「そのアロケータの完了」だけを待つ**
   ```cpp
   m_frameFenceValues[currentIndex] = m_commandQueue.Signal();
   // ↓ 次のフレームの先頭で
   m_commandQueue.WaitForFenceValue(m_frameFenceValues[nextIndex]);
   ```

`CommandQueue` クラスは `Signal()` と `WaitForFenceValue()` を分けて公開しているため、
この改善を行う準備はすでにできています。

## 7. 終了処理でやるべきこと

```cpp
renderer.WaitForGpu();   // ★ 必須
```

GPU がまだ使用中のリソースを解放すると、

- 終了時のクラッシュ
- デバッグレイヤーの「解放されていないリソースがある」警告

が発生します。

同様に、**スワップチェーンのリサイズ前にも必ず待つ**必要があります。
`Renderer::Resize` の先頭で `WaitForGpu()` を呼んでいるのはこのためです。
