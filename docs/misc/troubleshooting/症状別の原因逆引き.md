# 05. つまずきポイント集（症状別・原因逆引き）

DirectX 12 は **間違えてもコンパイルは通り、実行時にも例外が出ず、ただ「何も映らない」**
ということが頻繁に起きます。症状から原因を引けるようにまとめました。

---

## 0. まず最初にやること：デバッグレイヤーを確認する

起動ログに次の行があるか確認してください。

```
[INFO ] デバッグレイヤーを有効化しました（Debug ビルド）。
```

出ていない場合は、Windows の設定から **Graphics Tools** をインストールしてください
（[01 章](../setup/ビルドと実行方法.md#推奨-graphics-tools-のインストール)）。

デバッグレイヤーが有効なら、API の誤用は
Visual Studio の「出力」ウィンドウに具体的なメッセージとして表示されます。
**この一手間で解決時間が 10 分の 1 になります。**

---

## 症状 1: ウィンドウは出るが、真っ黒（クリア色すら出ない）

| 原因 | 確認する箇所 |
|------|------------|
| `Present()` を呼んでいない | `Renderer::Render` の末尾 |
| コマンドリストを `Close()` していない | `Close()` 忘れは `ExecuteCommandLists` でエラーになる |
| `ExecuteCommandLists` を呼んでいない | 記録しただけでは GPU は動かない |
| RTV のハンドルが間違っている | `CurrentRenderTargetView()` の `ptr` 計算 |
| バリアを張っていない | `PRESENT → RENDER_TARGET` |

---

## 症状 2: 背景（クリア色）は出るが、三角形が出ない

**最も多い症状です。** 上から順に確認してください。

### 2-1. シザー矩形が 0 のまま ★最頻出

```cpp
m_scissorRect = {};   // ← これだけだと right=0, bottom=0 で全ピクセルが捨てられる
```

`RSSetScissorRects` は **設定必須**です。ビューポートだけでは足りません。

> 該当コード: [`Renderer::UpdateViewportAndScissor`](../../../src/Graphics/Renderer.cpp)

### 2-2. 頂点の並び順（ワインディング）が逆 ★次点

DirectX の既定では **時計回りに見える面が表**です。
反時計回りだと裏面と判定され、背面カリングで消えます。

**切り分け方法:**

```cpp
// MeshPipeline.cpp のラスタライザ設定を一時的に変更する
rasterizerDesc.CullMode = D3D12_CULL_MODE_NONE;   // BACK → NONE
```

これで表示されたなら、原因は頂点の並び順です。

### 2-3. 座標が NDC の範囲外

頂点座標は **-1.0 〜 +1.0** の範囲でなければ画面に入りません。
`(0, 100, 0)` のようなピクセル単位の値を入れると、遥か画面外に飛びます。

（座標変換行列を導入するまでは NDC で直接指定します）

### 2-4. `SampleMask` が 0

```cpp
psoDesc.SampleMask = UINT_MAX;   // ← 0 にすると何も描画されない
```

`D3D12_GRAPHICS_PIPELINE_STATE_DESC` をゼロ初期化したまま設定を忘れると
`SampleMask = 0` になり、全ピクセルが破棄されます。

### 2-5. `SetPipelineState` / `SetGraphicsRootSignature` を呼んでいない

コマンドリストは `Reset` するたびに設定が消えます。**毎フレーム設定が必要**です。

### 2-6. `IASetPrimitiveTopology` を呼んでいない

PSO の `PrimitiveTopologyType`（大分類）だけでは足りず、
コマンドリスト側で `D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST`（具体的な結び方）の指定が必要です。

### 2-7. 頂点シェーダーが `w` を設定していない

```hlsl
output.position = float4(input.position, 1.0f);   // ← w = 1.0 が必要
```

`w = 0` だと透視除算でゼロ除算になり、結果が壊れます。

## 症状 3: 三角形は出るが、色や形がおかしい

### 3-1. 入力レイアウトのオフセットがずれている

**3 か所が一致している必要があります。**

```cpp
// (1) C++ の構造体
struct Vertex {
    float position[3];   // オフセット  0、12 バイト
    float color[4];      // オフセット 12、16 バイト
    float uv[2];         // オフセット 28、 8 バイト
};

// (2) 入力レイアウト
{ "POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT,    0,  0, ... },
{ "COLOR",    0, DXGI_FORMAT_R32G32B32A32_FLOAT, 0, 12, ... },  // ← 12 が正しいか
{ "TEXCOORD", 0, DXGI_FORMAT_R32G32_FLOAT,       0, 28, ... },  // ← 28 が正しいか
```

```hlsl
// (3) HLSL
struct VSInput {
    float3 position : POSITION;   // ← float3 と R32G32B32 が対応
    float4 color    : COLOR;      // ← float4 と R32G32B32A32 が対応
    float2 uv       : TEXCOORD;   // ← float2 と R32G32 が対応
};
```

**症状の見え方:** 形が崩れる／色が真っ黒や真っ白になる／頂点が飛ぶ。

### 3-2. `StrideInBytes` が構造体サイズと違う

```cpp
m_vertexBufferView.StrideInBytes = sizeof(Vertex);   // ハードコードしない
```

### 3-3. セマンティクス名の綴り違い

`"COLOR"` と `"COLOUR"`、`"POSITION"` と `"POSITIONS"` など。
**コンパイルは通ります。** その要素だけ値が 0 になります。

## 症状 3b: 座標変換を入れたら三角形が消えた・潰れた

### 3b-1. 行列を転置していない ★最頻出

C++ の DirectXMath は**行優先**、HLSL の定数バッファは既定で**列優先**です。
そのまま渡すと転置された行列として解釈されます。

```cpp
// 正しい
XMStoreFloat4x4(&constants.worldViewProjection, XMMatrixTranspose(wvp));

// 間違い（転置忘れ）
XMStoreFloat4x4(&constants.worldViewProjection, wvp);
```

**症状の見え方:** 三角形が画面外へ飛ぶ／潰れて線になる／変な方向に歪む。

### 3b-2. `mul()` の引数の順序が逆

```hlsl
mul(float4(input.position, 1.0f), g_wvp)   // 行ベクトル規約（DirectXMath と同じ）
mul(g_wvp, float4(input.position, 1.0f))   // 列ベクトル規約
```

転置の有無と組み合わせで 4 通りあり、正しいのは 2 通りだけです。
**「CPU で転置する + `mul(位置, 行列)`」**の組み合わせに統一するのが安全です。

### 3b-3. `w` を 1.0 にしていない

```hlsl
float4(input.position, 1.0f)   // ← 0.0f にすると透視除算でゼロ除算になる
```

### 3b-4. 回転させたら形が歪む

アスペクト比の補正が入っていません。
NDC は正方形ですが、ウィンドウは横長です。

```cpp
const XMMATRIX aspectCorrection = XMMatrixScaling(1.0f / aspectRatio, 1.0f, 1.0f);
```

### 3b-5. 定数バッファのサイズが 256 バイト境界に揃っていない

デバッグレイヤーが次のようなエラーを出します。

```
D3D12 ERROR: CreateConstantBufferView: SizeInBytes must be a multiple of 256
```

```cpp
const uint32_t alignedSize = (sizeInBytes + 255) & ~255u;
```

### 3b-6. 定数バッファを 1 個しか用意していない

フレームバッファリングと併用すると、
**CPU が書き込んでいる領域を GPU がまだ読んでいる**状態が発生します。

**症状の見え方:** ちらつく／回転がガタつく／たまに 1 フレームだけ飛ぶ。
再現性が低く、Debug ビルドでは気付きにくいのが厄介です。

コマンドアロケータと同様に、バックバッファの枚数ぶん用意してください。

### 3b-7. HLSL の `register(b0)` と C++ の番号が食い違う

```cpp
rootParameters[0].Descriptor.ShaderRegister = 0;   // ←→ HLSL: register(b0)
```

なお、`SetGraphicsRootConstantBufferView` の第 1 引数は
**ルートパラメータの番号**であって `b0` の `0` ではありません。
たまたま両方 0 のことが多いため、混同したまま気付かないことがあります。

## 症状 3c: 深度バッファを入れたら描画がおかしくなった

### 3c-1. 前後関係が逆に見える

`DepthEnable` が `FALSE` のままです。この場合
**あとから描いたものが必ず手前**になります。

```cpp
depthStencilDesc.DepthEnable    = TRUE;
depthStencilDesc.DepthWriteMask = D3D12_DEPTH_WRITE_MASK_ALL;
depthStencilDesc.DepthFunc      = D3D12_COMPARISON_FUNC_LESS;
```

`OMSetRenderTargets` の第 4 引数に DSV を渡し忘れている場合も同じ症状になります。

### 3c-2. 1 フレーム目は正常、2 フレーム目から真っ暗／ちらつく

`ClearDepthStencilView` を呼んでいません。
前フレームの深度が残るため、2 フレーム目以降のピクセルが
「すでに手前に何か描かれている」と判定されて全部捨てられます。

### 3c-3. PSO の生成が失敗する

`DSVFormat` が深度バッファの実際のフォーマットと食い違っています。

```cpp
psoDesc.DSVFormat = DepthBuffer::kFormat;   // DXGI_FORMAT_D32_FLOAT
```

### 3c-4. DSV の作成でエラーになる

リソース作成時に `D3D12_RESOURCE_FLAG_ALLOW_DEPTH_STENCIL` を立て忘れています。
このフラグが無いと「深度バッファとしては使えないリソース」になります。

### 3c-5. クリア値についての警告が出る

```
D3D12 WARNING: ClearDepthStencilView: The application did not pass a clear value
that matches the optimized clear value
```

`CreateCommittedResource` に渡した `D3D12_CLEAR_VALUE` と、
`ClearDepthStencilView` に渡す値が違います。両方 `kClearDepth` を使ってください。

### 3c-6. リサイズすると落ちる／エラーになる

深度バッファをレンダーターゲットと同じ解像度に作り直していません。
`Renderer::Resize` で **スワップチェーンと深度バッファの両方**を
リサイズする必要があります。

### 3c-7. 三角形が消える（z が範囲外）

深度は **0.0〜1.0** の範囲でなければなりません。
`DepthClipEnable = TRUE` のため、範囲外の頂点は切り取られます。
座標変換を入れていない段階では、頂点の z を 0.0〜1.0 に収めてください。

## 症状 3d: テクスチャを貼ったら真っ黒／真っ白／おかしい

### 3d-1. テクスチャが真っ黒 ★最頻出

`Shader4ComponentMapping` を設定していません。ゼロ初期化したままだと
全成分が 0 になり、読み出した色が必ず黒になります。

```cpp
srvDesc.Shader4ComponentMapping = D3D12_DEFAULT_SHADER_4_COMPONENT_MAPPING;
```

### 3d-2. `SetDescriptorHeaps` を呼んでいない

デバッグレイヤーが次のようなエラーを出します。

```
D3D12 ERROR: SetGraphicsRootDescriptorTable: The descriptor heap has not been set
```

`SetGraphicsRootDescriptorTable` より **前に** 呼ぶ必要があります。
コマンドリストを `Reset` するたびに消えるので、毎フレーム設定してください。

### 3d-3. CPU ハンドルを渡している

`SetGraphicsRootDescriptorTable` に渡すのは **GPU ハンドル**です。
CPU ハンドルとは値がまったく別物なので、渡し間違えると別の場所を指します。

### 3d-4. ヒープに `SHADER_VISIBLE` を付けていない

SRV / CBV / UAV は GPU 自身が読むため、このフラグが必須です。
付けていないヒープで `GetGPUDescriptorHandleForHeapStart()` を呼ぶと 0 が返ります。

逆に RTV / DSV 用ヒープに付けると生成が失敗します。

### 3d-5. テクスチャが上下逆さまに貼られる

UV の V は **下向きが正**です（画面の Y が上向きなのと逆）。
頂点の V を `1.0 - v` にするか、UV の与え方を見直してください。

### 3d-6. 画像が横に流れる・崩れる

中継バッファへのコピーで行ピッチを考慮していません。
1 行のバイト数は 256 バイト境界に揃えられるため、
**画像全体を一度に `memcpy` できません**。

```cpp
for (uint32_t row = 0; row < numRows; ++row) {
    memcpy(mapped + row * footprint.Footprint.RowPitch,   // 詰め物込みの行間隔
           source + row * width * 4,                       // 実データの行間隔
           rowSizeInBytes);
}
```

必要なサイズは `GetCopyableFootprints()` に問い合わせてください。

### 3d-7. 転送直後にクラッシュする

GPU のコピー完了を待たずに中継バッファを破棄しています。
`Initialize` を抜ける前に `commandQueue.Flush()` で待ってください。

### 3d-8. バリアを忘れている

転送後は `COPY_DEST` から `PIXEL_SHADER_RESOURCE` へ切り替える必要があります。

### 3d-9. `register(t0)` と C++ の番号が食い違う

```cpp
srvRange.BaseShaderRegister = 0;   // ←→ HLSL: register(t0)
staticSampler.ShaderRegister = 0;  // ←→ HLSL: register(s0)
```

なお `SetGraphicsRootDescriptorTable` の第 1 引数は
**ルートパラメータの番号**（登録順）であって `t0` の `0` ではありません。

## 症状 3e: 影を入れたらおかしくなった

### 3e-1. 床一面に縞模様（モアレ）が出る ★最頻出

**シャドウアクネ**です。バグではなく原理的に起きます。
シャドウマップに記録されているのは 1 テクセルぶんの代表値なので、
床が自分自身と比べたときに誤差で「影」と判定されるためです。

```cpp
rasterizerDesc.DepthBias            = 3000;
rasterizerDesc.SlopeScaledDepthBias = 2.5f;
```

第 1 パスの PSO で深度に下駄を履かせます。
詳しくは [13 章](../../tutorial/13_影を落とす_シャドウマップ.md#7-シャドウアクネ--必ず出る)。

### 3e-2. 影が物体から浮いている

**ピーターパン現象**です。深度バイアスを掛けすぎています。
`DepthBias` と `SlopeScaledDepthBias` を減らしてください。
アクネと浮きはトレードオフなので、見ながら調整するしかありません。

### 3e-3. 画面が真っ暗になる、または何も描かれない

第 2 パスで**ルートシグネチャを設定し直していない**可能性が高いです。

```cpp
commandList->SetGraphicsRootSignature(m_shadowRootSignature.Get());  // 第 1 パス
// ここまでに結び付けた定数バッファやテクスチャは全て無効になっている
```

ルートシグネチャを切り替えると、それまでのルートパラメータの結び付けは
**全て消えます**。第 2 パスの先頭で改めて設定してください。

なお `SetDescriptorHeaps()` は切り替えても残るので、1 フレームに 1 回で足ります。

### 3e-4. 画面全体が小さく描かれる／位置がおかしい

第 1 パスでビューポートをシャドウマップの大きさに変えたまま戻していません。

```cpp
commandList->RSSetViewports(1, &m_viewport);      // 第 2 パスの先頭で画面用に戻す
commandList->RSSetScissorRects(1, &m_scissorRect);
```

### 3e-5. SRV の作成でエラーになる

シャドウマップを `D32_FLOAT` で作っていませんか。
深度専用の形式はシェーダーから読めません。
本体は `R32_TYPELESS` で作り、DSV に `D32_FLOAT`、SRV に `R32_FLOAT` を指定します。

### 3e-6. 「書き込み中のリソースを読んでいる」とエラーが出る

リソースバリアの入れ忘れです。
第 1 パスの前に `PIXEL_SHADER_RESOURCE → DEPTH_WRITE`、
後に `DEPTH_WRITE → PIXEL_SHADER_RESOURCE` が要ります。

### 3e-7. 影の輪郭がガタガタで粗い

シャドウマップ 1 テクセルが担当する範囲が広すぎます。
`sceneRadius`（カバーする範囲）を狭めるか、解像度を上げてください。
**範囲を狭めるほうが効果は大きい**です。

### 3e-8. 影が真っ黒で物体の形が見えない

環境光にも影を掛けています。

```hlsl
diffuse  *= shadow;   // これは正しい
specular *= shadow;   // これも正しい
ambient  *= shadow;   // ★ これは間違い
```

環境光は周囲からの照り返しなので、太陽が遮られても残ります。

## 症状 3f: 入力・カメラ操作がおかしい

### 3f-1. マウスが効かない、または効いたり効かなかったり

`Input::NewFrame()` を**メッセージ処理の後**に呼んでいます。

```cpp
input.NewFrame();                 // ★ 先に区切る
if (!window.ProcessMessages()) { break; }
```

逆にすると、このフレームで届いた移動量を 0 に戻してしまいます。

### 3f-2. マウスの動きが遅い、大きく動かしても少ししか回らない

移動量を `+=` ではなく `=` で受けています。
`WM_MOUSEMOVE` は 1 フレームに何回も届くので、上書きすると最後の 1 回ぶんしか残りません。

### 3f-3. 最初にマウスを動かした瞬間に視点が吹き飛ぶ

前回位置の初期値 0 との差を取っています。
「まだ位置を受け取っていない」状態を持ち、最初の 1 回は差を取らないでください。

### 3f-4. 勢いよくドラッグすると途中で回転が止まる

`SetCapture()` を呼んでいません。
マウスがウィンドウの外へ出た時点で `WM_MOUSEMOVE` が届かなくなります。

### 3f-5. Alt+Tab から戻るとキーが押されっぱなしになる

`WM_KILLFOCUS` で状態を全て解除してください。
切り替え中に離したキーの `WM_KEYUP` は届きません。

### 3f-6. 真上まで回すと画面が消える

仰角の制限を掛けていません。
視線と上方向が平行になると `XMMatrixLookAtLH` が計算できなくなります。
`±87 度` 程度で `std::clamp` してください。

### 3f-7. 環境によって回転速度が違う

経過時間の掛け方を間違えています。

| 入力 | 経過時間 |
|------|---------|
| マウスの移動量（もう動いた距離） | **掛けない** |
| キーの押しっぱなし | **掛ける** |

キーに掛け忘れると FPS の高い環境ほど速く、
マウスに掛けると同じ操作でも FPS で結果が変わります。

### 3f-8. ウィンドウが「応答なし」になる

ウィンドウプロシージャの中で時間のかかる処理をしています。
メッセージ処理が滞ると OS へ応答が返りません。
プロシージャでは**記録するだけ**にして、処理はメインループで行ってください。

## 症状 3g: モデルを読み込んだら表示がおかしい

### 3g-1. 前後が逆になっている気がする ★見つけにくい

右手座標系から左手座標系への変換を忘れています。

```cpp
position[2] = -position[2];
normal[2]   = -normal[2];
```

**モデルは消えも裏返りもせず、前後が鏡写しになるだけ**なので気付きにくい間違いです。
さらに左右対称なモデル（球・ドーナツ・立方体など）では
**まったく同じ絵になる**ため、対称なモデルでは検証できません。
非対称なモデルで確かめてください。

### 3g-2. モデルが真っ黒、または陰影がまだら

法線が壊れています。次のどれかです。

- `vn` の Z を反転し忘れた（座標だけ反転すると法線と食い違う）
- 法線を自動生成するとき、**頂点ではなく座標**で足し合わせていない
- 正規化を忘れている

### 3g-3. 角が丸く見える／欲しい所に折り目が出ない

`vn` の無いファイルを読み込み、法線を自動生成しています。
この方法は必ず滑らかにつながるため、角が立ちません。
角を残したいなら、ファイル側に `vn` を書くか、面ごとに頂点を分けてください。

### 3g-4. テクスチャが上下逆に貼られる

OBJ の V は下から上へ、DirectX の V は上から下へ増えます。

```cpp
uv[1] = 1.0f - uv[1];
```

### 3g-5. モデルが巨大すぎる／小さすぎて見えない

モデルの単位はファイルによって違います（メートル・センチ・インチ…）。
バウンディングボックスを求めて、決めた大きさに揃えてください。

### 3g-6. 一部の面だけ表示されない、または変な三角形が出る

多角形のファン分割は**凸多角形でしか正しくありません**。
へこんだ面があると、多角形の外へはみ出す三角形ができます。

### 3g-7. 「頂点が多すぎます」で読み込みに失敗する

インデックスを 16 ビット (`R16_UINT`) で持っているため、
頂点は 65536 個未満に限られます。
それ以上のモデルを扱うには `DXGI_FORMAT_R32_UINT` へ変更してください。

### 3g-8. 変更したはずのコードが反映されない

バックアップから `Copy-Item` でソースを書き戻したときに起きます。
`Copy-Item` は**元ファイルの更新日時をそのまま引き継ぐ**ため、
中間ファイル (`.obj`) より古い日時になり、MSBuild が再コンパイルを省きます。

対処は、対応する中間ファイルを消してからビルドすることです。

```powershell
Remove-Item build\intermediate\x64\Debug\ObjLoader.obj
```

## 症状 3h: glTF を読み込んだらおかしい

### 3h-1. 一部の頂点だけ値が飛ぶ、形が壊れる

`byteOffset` は **accessor と bufferView の両方**にあります。**足してください**。

```cpp
const size_t base = viewOffset + accessorOffset;
```

片方だけ使うと、ほとんどのファイルでは動くのに一部で壊れます。
最適化されたファイルほど両方に値が入っているためです。

### 3h-2. 座標がめちゃくちゃになる

`byteStride` を見ていません。
複数の属性が交互に並んでいる（インターリーブ）と、要素は連続していません。

```cpp
const size_t stride = bufferView.Member("byteStride")
                        ? ... : tightStride;
```

### 3h-3. UV が真っ黒、または極端な値になる

`normalized` を見ていません。
UV や色は `uint8` / `uint16` に圧縮されていることがあり、
その場合は `255` や `65535` で割って `0.0〜1.0` に戻す必要があります。

### 3h-4. テクスチャが上下逆に貼られる

**glTF の UV は反転しません。** 左上が原点で、DirectX と同じだからです。
OBJ の癖で `1.0 - v` と書いてしまうと逆になります。

### 3h-5. 部品の位置がバラバラ、全部原点に固まる

ノードの変換を適用していません。
glTF のノードは入れ子にでき、**変換は親から積み重なります**。

```cpp
const XMMATRIX transform = LocalTransformOf(node) * parentTransform;
```

### 3h-6. モデルが妙に歪む、回転がおかしい

`matrix` は**列優先**で並んでいます。DirectXMath は行優先なので読み替えが要ります。
また TRS の適用順は **拡大縮小 → 回転 → 平行移動**で、順序を変えると結果が変わります。

### 3h-7. 拡大縮小したノードだけ陰影がおかしい

法線を位置と同じ行列で変換しています。
軸ごとに違う倍率だと面に垂直でなくなるため、**逆行列の転置**を使ってください。

```cpp
XMMATRIX normalTransform = XMMatrixTranspose(XMMatrixInverse(nullptr, transform));
```

### 3h-8. `.glb` は読めるが `.gltf` が読めない（またはその逆）

buffer の実体には 3 通りの置き場所があります。

| 置き場所 | 見分け方 |
|---------|---------|
| GLB のバイナリチャンク | `uri` が無い |
| 埋め込み | `uri` が `data:...;base64,` で始まる |
| 外部ファイル | `uri` が相対パス |

3 つとも扱えるようにしてください。

## 症状 3i: 画像ファイルを読み込めない・おかしい

### 3i-1. `CoCreateInstance` が 0x800401F0 で失敗する

COM を初期化していません。WIC は COM のオブジェクトです。

```cpp
const dx12::ComInitializer comInitializer;   // main の先頭で 1 つ
```

DirectX 12 自体は COM の初期化を必要としないため、
WIC を使い始めるまで気付きません。

### 3i-2. 画像が斜めに流れる・崩れる

`CopyPixels` に渡すストライドが違います。RGBA8 なら「幅 × 4」です。

なお、GPU への中継バッファでは 256 バイト境界に揃える必要があり、
**こちらとは別の値**です。混同しないでください。

### 3i-3. 色がおかしい（赤と青が入れ替わる）

変換先の形式が `32bppBGRA` になっています。
本プロジェクトのテクスチャは `DXGI_FORMAT_R8G8B8A8_UNORM` なので、
`GUID_WICPixelFormat32bppRGBA` を指定してください。

### 3i-4. 画像によって表示されたりされなかったりする

`IWICFormatConverter` を通さず、`frame->CopyPixels()` を直接呼んでいます。
元の形式のまま返るため、24bit BMP なら 3 バイト、
グレースケールなら 1 バイトになり、RGBA8 を前提としたコードが破綻します。

### 3i-5. テクスチャが上下逆に貼られる

WIC は上から下へ並べて返します。`Texture2D` もその前提です。
逆になるならモデル側の UV か、読み込み時の V 反転を疑ってください
（OBJ は反転が必要、glTF は不要）。

**市松模様のような対称な絵では、この症状に気付けません。**
検証には向きの分かる絵（本プロジェクトの `uv-grid.png`）を使ってください。

### 3i-6. リンクで `IWICImagingFactory` が見つからない

`windowscodecs.lib` をリンクしていません。

## 症状 3j: マテリアルがおかしい

### 3j-1. モデル全体が 1 色になる

サブメッシュに分けず、メッシュ全体を 1 回で描いています。
材質が変わるたびに `DrawIndexedInstanced` を区切ってください。

### 3j-2. 最後の材質の部分が描かれない

OBJ で、ファイルの末尾でサブメッシュを閉じていません。
`usemtl` が来たときだけ閉じていると、**最後の `usemtl` 以降が丸ごと消えます**。

### 3j-3. 色が二重に暗くなる

頂点カラーと材質の基本色を両方掛けています。
どちらか一方に決めてください。本プロジェクトは
「読み込んだモデルの頂点カラーは白、色は材質が持つ」に統一しています。

### 3j-4. テクスチャの無い材質が真っ黒になる

テクスチャを結び付けずに描いています。前の材質のテクスチャが残っているか、
何も設定されていない状態です。

白 1 ピクセルの画像を割り当てると、分岐なしで解決します。

### 3j-5. `map_Kd` のパスが途中で切れる

`>>` で読むと空白で切れます。行の残り全部を `std::getline` で読んでください。
`Program Files` のようなフォルダ名で表面化します。

### 3j-6. glTF の埋め込み画像が読めない

`images[].bufferView` を見ていません。glTF の画像は buffers と同じく
**GLB のチャンク内・data URI・外部ファイル**の 3 通りがあります。

### 3j-7. 材質を差し替えても反映されない

ディスクリプタテーブルではなく、ルートディスクリプタで
テクスチャを渡そうとしています。SRV はテーブル経由でしか渡せません。

### 3j-8. 影だけおかしい

影のパスで材質ごとに区切る必要はありません（深度しか書かないため）。
逆に、影のパスでも `BindObject` は必要です。忘れると影の位置がずれます。

## 症状 3k: 色空間まわりがおかしい

### 3k-1. 画面全体が白っぽく、あるいは黒っぽくなった

sRGB の変換が片側だけ効いています。
入口（テクスチャ）と出口（レンダーターゲット）は**必ず両方**揃えてください。

片方だけだと、変換が 1 回余分に掛かる（明るくなる）か、
1 回足りない（暗くなる）ことになります。

### 3k-2. `_SRGB` を付けたらスワップチェーンの生成に失敗する

フリップモデル (`FLIP_DISCARD`) では、**スワップチェーン本体に `_SRGB` を指定できません**。

```cpp
// 本体は通常の形式
kBackBufferFormat = DXGI_FORMAT_R8G8B8A8_UNORM;

// RTV 側で sRGB を指定する
kRenderTargetViewFormat = DXGI_FORMAT_R8G8B8A8_UNORM_SRGB;
```

### 3k-3. 実行時に「レンダーターゲットの形式が合わない」と言われる

PSO の `RTVFormats[0]` に、スワップチェーン本体の形式を渡しています。
**RTV の形式（`_SRGB` 付き）**を渡してください。

PSO の生成自体は通ってしまうので、実行するまで気付けません。

### 3k-4. 背景の色が急に明るくなった

`ClearRenderTargetView` に渡す値も、RTV が sRGB なら**リニアとして解釈**されます。
これまでと同じ値を渡すと明るくなります。リニアの値へ直してください。

### 3k-5. 法線マップを使ったら表面がおかしい

法線マップに `_SRGB` を付けています。
あれは色ではなく**ベクトルの成分**なので、変換してはいけません。
粗さ・金属度・高さマップも同様です。

### 3k-6. 明るい部分が真っ白に潰れる

トーンマッピングを入れていません。
リニア空間の明るさは 1.0 を超えるため、そのまま書くと切り落とされます。

本プロジェクトの実測では、トーンマッピング無しで **556 画素**が 255 に張り付き、
有りで **0 画素**になりました。

### 3k-7. 影の中が明るくなった

**それが正しい状態です。** これまでが暗すぎました。
リニアの 0.25 を sRGB へ変換すると 0.54 になります。

## 症状 3m: PBR にしたら見え方がおかしい

### 3m-1. 金属が真っ黒になる

**IBL（環境マップ）を入れる前なら、それが正しい状態です。**
金属には拡散反射が無く、映り込みだけで見えています。
環境マップが無ければ、光源が直接反射する場所以外は真っ暗になります。

IBL を入れてもまだ黒いなら、[症状 3n](#症状-3n-ibl-環境マップを入れたら見え方がおかしい) を見てください。

### 3m-2. 全体が 1/3 ほど暗くなった

拡散反射を π で割ったぶんの埋め合わせをしていません。
光の強さに π を掛けるか、割るのをやめてください（前者が物理的に素直です）。

### 3m-3. 粗さを 0 にするとちらつく・白い点が飛ぶ

GGX の分母が 0 に近づいて数値が破綻しています。
粗さに下限（0.03 程度）を設けてください。

### 3m-4. 金属度・粗さのテクスチャを使うと質感が変わってしまう

その画像を sRGB として読んでいます。
**色ではなく数値**なので、変換してはいけません。
粗さ 0.5 が 0.21 になってしまいます。

### 3m-5. チャンネルの割り当てが合わない

glTF の決まりは **緑が粗さ、青が金属度**です。赤は遮蔽（本プロジェクトは未使用）。
`r` と `b` を取り違えると、金属と粗さが入れ替わります。

### 3m-6. ハイライトが四角い、または妙に暗い

分母の `4 * NdotV * NdotL` を入れていないか、0 で割っています。
`max(..., 1e-4f)` のような下限を入れてください。

### 3m-7. glTF を読むと何もかも金属になる

`metallicFactor` の**既定値は 1.0** です（`roughnessFactor` も同じ）。
書かれていないファイルは「粗い金属」として扱われます。
規格どおりの振る舞いですが、意図しない見え方になったら疑ってください。

## 症状 3n: IBL（環境マップ）を入れたら見え方がおかしい

### 3n-1. 粗さを変えても映り込みのぼけ方が変わらない

`Sample` を使っています。`Sample` は画面上での変化量から段を自動で選ぶため、
粗さは反映されません。段を明示する **`SampleLevel`** に変えてください。

```hlsl
g_environment.SampleLevel(g_sampler, uv, roughness * (mipCount - 1.0f))
```

### 3n-2. `SampleLevel` にしたのに、いつも同じ鮮明さで返る

SRV の `MipLevels` が 1 のままです。段数を入れてください。

```cpp
srvDesc.Texture2D.MipLevels = mipCount;
```

`MipLevels` が 1 だと、後ろの段を指定しても 0 段目しか読めません。

### 3n-3. ミップの 2 段目以降が真っ黒、またはノイズだらけ

転送先のサブリソースを取り違えています。
段ごとに `CopyTextureRegion` を呼び、`SubresourceIndex` に段番号を渡します。

配置（オフセット・行ピッチ）は自分で計算せず、
`GetCopyableFootprints` に段数ぶんまとめて出してもらってください。

### 3n-4. 環境光を足したら全体が眠たい灰色になった

**縮小やぼかしを sRGB のまま行っています。** 平均はリニアでなければ
意味を持ちません。読むときに `SrgbToLinear`、書くときに `LinearToSrgb` を
通してください。

### 3n-5. 真上と真下ばかり明るくなる

イラディアンスの積分で**立体角の補正（`sin θ`）**を忘れています。
正距円筒図法では、極に近い行ほど画像上では横幅いっぱいを占めるのに、
実際にはごく狭い方向しか表していません。

```cpp
const float solidAngle = std::sin(lightTheta);
const float weight = cosine * solidAngle;
```

### 3n-6. 映り込みの継ぎ目に縦線が出る

環境マップの左右がつながっていません。
横方向のアドレスモードを **WRAP** にしてください。
ぼかしを CPU 側でかけるときも、横は巻き戻して参照します。

### 3n-7. 太陽が眩しくならない

8 bit の PNG では明るさが 1.0 で頭打ちになります。
眩しさを出すには HDR の環境マップ（`.hdr` / `.exr`）と
浮動小数点フォーマットのテクスチャが要ります。

### 3n-8. くぼみや隙間まで明るく、全体が浮いて見える

遮蔽を考慮していないためです。IBL は「空がどこからでも見える」前提で
光を入れます。SSAO や遮蔽マップ（glTF の `occlusionTexture`）が要ります。

### 3n-9. 環境光を足したら白飛びした

アンビエントの強さが二重に効いています。
定数アンビエントを IBL に置き換えたなら、**元の定数は消すか、
意味を「IBL の倍率」に変えて 1.0 にする**かのどちらかにしてください。

## 症状 3o: 法線マップを入れたら見え方がおかしい

### 3o-1. 面が全部、同じ向きに傾いて見える

法線マップを **sRGB として読んでいます**。色ではなく座標なので、
変換してはいけません。`0.5`（傾き 0）が `0.21` になってしまいます。

```cpp
texture->Initialize(..., /* isColorTexture */ false);
```

### 3o-2. 凹凸が逆（へこみが出っ張って見える）

従接線の符号 `w` が反転しています。glTF を読むときは、
**右手系から左手系へ移したぶん符号も反転**させてください。

```cpp
vertex.tangent[3] = -tangents[v * tangentComponents + 3];
```

緑チャンネルの向き（OpenGL 式と DirectX 式）が食い違っている可能性もあります。

### 3o-3. 模様がぐちゃぐちゃ、または画面が真っ暗

入力レイアウトのオフセットが `Vertex` 構造体とずれています。
**実行はできてしまう**ので、`static_assert` で機械的に止めてください。

```cpp
static_assert(sizeof(Vertex) == 64, "...");
static_assert(offsetof(Vertex, tangent) == 48, "...");
```

### 3o-4. 効果がまったく出ない

- 材質に法線マップが設定されていない（代用の平らな 1 ピクセルのまま）
- `normalScale` が 0 になっている
- glTF の `normalTexture` を `pbrMetallicRoughness` の**内側**で探している
  （正しくは**外側**）

### 3o-5. 一部の面だけ真っ黒、または継ぎ目が出る

接線が求まっていません。UV が潰れている面（3 頂点が同じ UV を指す）では
計算できないので、法線と直交する適当な向きで埋めてください。

### 3o-6. 輪郭が平らなままで嘘っぽい

**それが仕組みの限界です。** 法線マップは光の当たり方を変えるだけで、
面の形は変えていません。輪郭も変えたいなら
ディスプレイスメントマッピングやテッセレーションが要ります。

### 3o-7. 凹凸が影を落とさない

位置を変えていないため、シャドウマップの結果は変わりません。
凹凸どうしが隠し合うようにするには視差遮蔽マッピングが要ります。

### 3o-8. 遠くの床がちらちらする

法線マップにミップマップがありません。縮小されると隣り合うテクセルの
向きが混ざり、フレームごとに違う値を拾ってちらつきます。

## 症状 4: 実行中にクラッシュ・デバッガが止まる

### 4-1. `SetBreakOnSeverity` によるブレーク（正常な動作）

```cpp
infoQueue->SetBreakOnSeverity(D3D12_MESSAGE_SEVERITY_ERROR, TRUE);
```

これは**わざと止めています**。「出力」ウィンドウにエラーの内容が出ているので読んでください。
原因の場所で止まっているため、最も解決しやすい状態です。

### 4-2. コマンドアロケータを GPU 実行中に Reset

```
アロケータの Reset は、そのアロケータで記録した命令の実行完了後でなければならない
```

本プロジェクトは毎フレーム `Flush()` しているため発生しませんが、
フレームバッファリングに改造したときに最も嵌まりやすい箇所です。

### 4-3. `StateBefore` が実際の状態と違う

```cpp
barrier.Transition.StateBefore = D3D12_RESOURCE_STATE_PRESENT;   // 実際と一致必須
```

DirectX 12 はリソースの状態を追跡してくれません。開発者が正しく把握する必要があります。

### 4-4. リサイズ時にバックバッファの参照が残っている

`ResizeBuffers` の前に **すべての参照を手放す**必要があります。

```cpp
for (auto& backBuffer : m_backBuffers) {
    backBuffer.Reset();   // ComPtr の参照カウントを減らす
}
```

1 つでも残っていると `DXGI_ERROR_INVALID_CALL` で失敗します。

### 4-5. 終了時にクラッシュ・リソースリーク警告

GPU の作業完了を待たずにリソースを解放しています。

```cpp
renderer.WaitForGpu();   // 終了前に必ず
```

## 便利な切り分けテクニック

### 1. ワイヤーフレーム表示

```cpp
rasterizerDesc.FillMode = D3D12_FILL_MODE_WIREFRAME;
```

「三角形は描かれているが色が黒」なのか「そもそも描かれていない」のかを判別できます。

### 2. クリア色を派手にする

```cpp
constexpr float kClearColor[4] = { 1.0f, 0.0f, 1.0f, 1.0f };  // マゼンタ
```

クリアすら効いていないのかを一目で判定できます。

### 3. ピクセルシェーダーで固定色を返す

```hlsl
float4 PSMain(VSOutput input) : SV_TARGET
{
    return float4(1, 1, 0, 1);   // 黄色固定
}
```

黄色い三角形が出れば、**ジオメトリ（頂点処理）は正しく、色の受け渡しに問題がある**と分かります。

### 4. カリングを切る

```cpp
rasterizerDesc.CullMode = D3D12_CULL_MODE_NONE;
```

これで出るなら頂点の並び順の問題です。

### 5. Visual Studio のグラフィックスデバッガ

`Alt + F5` でグラフィックスデバッグを開始し、`Print Screen` でフレームをキャプチャ。
描画命令を 1 つずつ辿り、各段階での状態を確認できます。
「どの設定が想定と違うか」を直接見られるため、行き詰まったときに極めて有効です。
